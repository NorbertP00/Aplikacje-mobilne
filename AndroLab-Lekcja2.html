TEMAT 2

Układy, widoki i pierwsza interakcja z użytkownikiem

Poznaj LinearLayout, kluczowe widżety i naucz się łączyć kod XML z logiką w Javie — to fundament każdego zadania na egzaminie.

Co musisz umieć na egzaminie INF.04?

Układ ekranu (XML)

Poprawna budowa layoutu: LinearLayout z widżetami TextView, EditText i Button — każdy na właściwym miejscu.

Atrybut android:id

Unikalny identyfikator każdego widżetu — niezbędny, by pobrać go w Javie metodą findViewById().

Obsługa kliknięcia

Podpięcie akcji do przycisku przez setOnClickListener() i wyświetlenie wyniku — np. Toast albo zmiana tekstu.

Pobranie danych z pola

Odczyt tego, co użytkownik wpisał w EditText, przez .getText().toString() i użycie tego w logice aplikacji.

Trzy pojęcia, które będą w każdym zadaniu

Układ (Layout)

JAK wygląda aplikacja. Pliki .xml w katalogu res/layout — sposób rozmieszczenia elementów na ekranie.

Aktywność (Activity)

CO robi aplikacja. Pliki .java w katalogu java — np. reakcja na wciśnięcie przycisku.

Widok (View / widżet)

Element umieszczony w układzie: pole tekstowe TextView, pole edycyjne EditText, przycisk Button.

Wymiary i napisy

match_parent rozciąga element do rozmiaru rodzica (np. na pełną szerokość ekranu), a wrap_content dopasowuje go do zawartości (np. do długości napisu na przycisku). W LinearLayout atrybut android:orientation ustawia elementy jeden pod drugim (vertical) albo obok siebie (horizontal). Napisy trzymamy w pliku strings.xml (katalog res/values) i wstawiamy przez @string/nazwa — tekst wpisany na sztywno to żółte ostrzeżenie hardcoded text.

Warning kontra Error

⚠ Warning (żółty)

Sygnał „można napisać lepiej” — aplikacja mimo to się uruchomi. Przykład: hardcoded text.

⛔ Error (czerwony)

Emulator nie uruchomi aplikacji z błędem — najpierw trzeba go naprawić. Przykład: błąd składni XML, nieznany symbol.

Schemat każdego zadania egzaminacyjnego

Kliknięcie→onClick()→pobierz dane→wyświetl wynik

Bez względu na treść zadania zawsze powtarza się ten sam wzorzec: kliknięcie → pobranie danych → przetworzenie → wyświetlenie wyniku. Gotowe wzorce kodu znajdziesz w zakładce Ściąga, a wszystko przećwiczysz w Placu zabaw.

KROK 2

Podstawowe pojęcia — Układ, Aktywność, Widok

Te trzy pojęcia będą się pojawiać w każdym zadaniu egzaminacyjnym.

Układ (Layout)

Sposób rozmieszczenia elementów na ekranie. Pliki układów leżą w katalogu res/layout i zawsze mają rozszerzenie .xml. To tu definiujemy, JAK wygląda aplikacja.

Aktywność (Activity)

Działanie, jakie wykonuje aplikacja — np. reakcja na wciśnięcie przycisku. Pliki .java w katalogu java. To tu definiujemy, CO robi aplikacja.

Widok (View / widżet)

Element umieszczony w układzie: pole tekstowe TextView, pole edycyjne EditText, przycisk Button.

KROK 3

Układ liniowy — LinearLayout

Cecha charakterystyczna LinearLayout: każdy element jest układany jeden po drugim — w kolejności, w jakiej jest wpisany w pliku XML.

<?xml version="1.0" encoding="utf-8"?>
<LinearLayout
  xmlns:android="http://schemas.android.com/apk/res/android"
  android:layout_width="match_parent"
  android:layout_height="wrap_content"
  android:orientation="vertical">

  <TextView
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:text="@string/tekst1" />

  <Button
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:text="@string/przycisk1" />

  <Button
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="@string/przycisk2" />

</LinearLayout>
android:orientation

vertical — elementy jeden pod drugim; horizontal — elementy obok siebie.

match_parent

Rozciąga element do rozmiaru rodzica — np. do pełnej szerokości ekranu.

wrap_content

Dopasowuje rozmiar do zawartości — np. do długości napisu na przycisku.

Po uruchomieniu Przycisk 1 (match_parent) jest rozciągnięty na pełną szerokość ekranu, a Przycisk 2 (wrap_content) ma szerokość dopasowaną do napisu.

KROK 4

Plik strings.xml — zasoby tekstowe

Dlaczego unikać hardcoded text? Android Studio zgłasza ostrzeżenie (warning), gdy tekst jest wpisany bezpośrednio w układzie. Hardcoding utrudnia też tłumaczenie aplikacji na inne języki.

<resources>
  <string name="app_name">Aplikacja2</string>
  <string name="tekst1">Witaj programisto</string>
  <string name="przycisk1">To jest przycisk 1</string>
  <string name="przycisk2">To jest przycisk 2</string>
</resources>

Odwołanie do zasobu w układzie. Znak @ informuje, że sięgamy do innego pliku; po ukośniku podajemy nazwę łańcucha.

android:text="@string/tekst1"
android:text="@string/przycisk1"
android:text="@string/przycisk2"

Wygląd aplikacji nie zmienia się — z edytora znikają tylko żółte ostrzeżenia.

Trzy najważniejsze katalogi projektu to: manifests, java i res. Plik strings.xml znajdziemy w katalogu res/values.

KROK 5

Warning a Error — rodzaje błędów

⚠ Warning (ostrzeżenie)

Oznaczony żółtym kolorem. Sygnał, że coś można napisać lepiej — ale aplikacja uruchomi się mimo ostrzeżeń. Przykład: hardcoded text.

⛔ Error (błąd)

Oznaczony czerwonym kolorem. Emulator nie uruchomi aplikacji, w której znajdzie Error — np. brakującą klasę, nieznany symbol, błąd składni XML. Napraw go przed uruchomieniem!

Jak ponownie uruchomić aplikację po zmianach? Kliknij zieloną zaokrągloną strzałkę (przycisk Rerun) w górnym pasku narzędzi — Android Studio skompiluje projekt od nowa i załaduje zmiany w emulatorze.

KROK 6 — EGZAMIN!

Atrybut android:id — klucz do Javy

Do tej pory budowaliśmy tylko wygląd aplikacji. Czas połączyć interfejs XML z kodem Java — podstawą tego połączenia jest atrybut android:id, który nadaje widżetowi unikalny identyfikator.

<TextView
    android:id="@+id/tekstPowitania"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:text="@string/tekst1" />

<EditText
    android:id="@+id/poleImie"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:hint="Wpisz swoje imię" />

<Button
    android:id="@+id/przyciskWitaj"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:text="Przywitaj mnie" />
Składnia: @+id/nazwaWidzetu

Znak @+id/ tworzy nowy identyfikator w pliku zasobów R.java. Nazwę po ukośniku nadawaj opisowo, np. poleImie, przyciskWitaj.

android:hint — podpowiedź

Wyświetla szarą podpowiedź wewnątrz pustego pola EditText. Znika automatycznie, gdy użytkownik zaczyna pisać.

KROK 7 — EGZAMIN!

Nowy widżet: EditText — pole do wpisywania tekstu

EditText to pole edycyjne, w którym użytkownik może wpisać tekst — pojawia się w niemal każdym zadaniu mobilnym INF.04.

android:hint

Szara podpowiedź w pustym polu — informuje użytkownika, co wpisać.

android:inputType

Typ klawiatury: text, textPersonName, number, phone — dopasowuje klawiaturę do rodzaju danych.

android:id — obowiązkowy!

Bez id nie pobierzemy wartości pola w Javie. Zawsze nadawaj id widżetom używanym w kodzie.

KROK 8 — EGZAMIN!

Łączenie XML z Javą — metoda findViewById()

Aby używać widżetów w kodzie Java, musimy je najpierw „odnaleźć" metodą findViewById() — przekazujemy jej identyfikator, a ona zwraca obiekt, którym możemy sterować.

public class MainActivity extends AppCompatActivity {

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        // Pobieramy widżety z układu XML za pomocą ich id
        TextView tekstPowitania = (TextView) findViewById(R.id.tekstPowitania);
        EditText poleImie       = (EditText) findViewById(R.id.poleImie);
        Button   przyciskWitaj  = (Button)   findViewById(R.id.przyciskWitaj);
    }
}
R.id.nazwaWidzetu

Android generuje plik R.java z ID wszystkich zasobów. Piszemy R.id. i podajemy nazwę z atrybutu android:id.

Rzutowanie (casting)

Nawias z typem, np. (TextView), informuje Javę, jaki obiekt pobieramy. W nowych wersjach Android Studio można go pominąć.

Kolejność ma znaczenie!

setContentView() MUSI być przed findViewById(). Najpierw ładujemy układ, potem szukamy w nim widżetów. Odwrotnie = błąd!

KROK 9 — EGZAMIN!

Obsługa kliknięcia — setOnClickListener()

Gdy użytkownik klika przycisk, Java musi zareagować. Metodę setOnClickListener() podpinamy pod obiekt Button, a wewnątrz piszemy kod, który ma się wykonać po kliknięciu.

przyciskWitaj.setOnClickListener(new View.OnClickListener() {
    @Override
    public void onClick(View v) {
        // Pobieramy tekst z pola EditText
        String imie = poleImie.getText().toString();
        // Wyświetlamy wynik w TextView
        tekstPowitania.setText("Witaj, " + imie + "!");
    }
});
setOnClickListener()

Metoda przypisana do obiektu Button — reaguje na każde kliknięcie przycisku.

onClick(View v)

Wywoływana automatycznie przy każdym kliknięciu. Tu piszemy całą logikę działania przycisku.

.getText().toString()

Pobiera tekst wpisany w EditText i zamienia go na typ String.

.setText("tekst")

Ustawia nowy tekst w widżecie TextView — wyświetla wynik na ekranie.

KROK 10 — EGZAMIN!

Toast — krótki komunikat wyskakujący

Toast pojawia się na ekranie na kilka sekund i znika automatycznie. Na egzaminie to częsty sposób wyświetlania wyniku działania przycisku.

Toast.makeText(
    getApplicationContext(),
    "Witaj, " + imie + "!",
    Toast.LENGTH_SHORT
).show();
Toast.makeText()

Tworzy obiekt komunikatu. Przyjmuje 3 parametry: kontekst (getApplicationContext()), tekst wiadomości i czas wyświetlania.

Toast.LENGTH_SHORT

Komunikat widać przez ok. 2 sekundy. Użyj LENGTH_LONG dla ok. 3,5 sekundy.

.show()

Obowiązkowe wywołanie na końcu! Bez .show() Toast zostanie utworzony, ale nie pokaże się na ekranie.

Aby użyć Toast, dodaj import na początku pliku: import android.widget.Toast;

KROK 11 — EGZAMIN!

Widżety egzaminacyjne — SeekBar i kolory tła

SeekBar (suwak) pozwala wybrać wartość z zakresu — pojawia się w wielu zadaniach (np. „Właściwości czcionki" 2023, „Urządzenia domowe" 2025).

<SeekBar
  android:id="@+id/suwak"
  android:layout_width="match_parent"
  android:layout_height="wrap_content"
  android:max="40" />
suwak.setOnSeekBarChangeListener(
  new SeekBar.OnSeekBarChangeListener() {
    @Override
    public void onProgressChanged(SeekBar s,
            int progress, boolean fromUser) {
        // progress = aktualna wartość suwaka
        labelWynik.setText("Wartość: " + progress);
    }
    @Override
    public void onStartTrackingTouch(SeekBar s) {}
    @Override
    public void onStopTrackingTouch(SeekBar s) {}
});

Kolory tła widżetów. Na egzaminie CKE często podany jest konkretny kolor (np. #558B2F). Ustawiamy go atrybutem android:background (TextView/LinearLayout) lub android:backgroundTint (Button).

<!-- Kolor tła TextView lub LinearLayout -->
<TextView
  android:background="#558B2F"
  android:textColor="#FFFFFF" />

<!-- Kolor tła przycisku -->
<Button
  android:backgroundTint="#558B2F"
  android:textColor="#FFFFFF" />

<!-- Marginesy dla całej strony -->
<LinearLayout
  android:padding="20dp" />
Na egzaminie zawsze czytaj uważnie wymagania dotyczące kolorów i marginesów — są podane wprost w arkuszu i sprawdzane przez egzaminatora!
KROK 12 — EGZAMIN!

Tablice w Javie — cykliczne przełączanie treści

Częste zadanie CKE: przycisk cyklicznie przełącza między kilkoma wartościami. Rozwiązanie: tablica + licznik indeksu jako pole klasy.

public class MainActivity extends AppCompatActivity {

    String[] cytaty = {"Dzień dobry", "Good morning", "Buenos dias"};
    int aktualny = 0;   // pole klasy — POZA onCreate!

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);
        setContentView(R.layout.activity_main);

        TextView labelCytat = (TextView) findViewById(R.id.labelCytat);
        Button btnNastepny  = (Button)   findViewById(R.id.btnNastepny);

        labelCytat.setText(cytaty[0]);   // pierwszy element na starcie

        btnNastepny.setOnClickListener(new View.OnClickListener() {
            @Override
            public void onClick(View v) {
                aktualny++;
                if (aktualny >= cytaty.length) {
                    aktualny = 0;   // po ostatnim wracamy do początku
                }
                labelCytat.setText(cytaty[aktualny]);
            }
        });
    }
}
cytaty[0]

Dostęp do elementu tablicy po indeksie — numeracja od zera.

cytaty.length

Długość tablicy (liczba elementów).

aktualny++

Zwiększenie indeksu o 1.

Zmienna „aktualny"

Musi być polem klasy (poza onCreate), żeby zachować wartość między kliknięciami.

Ten schemat pojawił się na egzaminie w czerwcu 2023 („Właściwości czcionki") — tablica 3 cytatów przełączanych przyciskiem. Zapamiętaj go! W Placu zabaw wczytasz go jako gotowy przykład.

Plik MainActivity.java

import androidx.appcompat.app.AppCompatActivity;
import android.os.Bundle;
import android.view.View;
import android.widget.Button;
import android.widget.EditText;
import android.widget.TextView;
import android.widget.Toast;

public class MainActivity
        extends AppCompatActivity {

  @Override
  protected void onCreate(Bundle savedInstanceState) {
    super.onCreate(savedInstanceState);
    setContentView(R.layout.activity_main);

    TextView labelWynik =
        (TextView) findViewById(R.id.labelWynik);
    EditText poleImie =
        (EditText) findViewById(R.id.poleImie);
    Button btnWitaj =
        (Button) findViewById(R.id.btnWitaj);

    btnWitaj.setOnClickListener(
        new View.OnClickListener() {
      @Override
      public void onClick(View v) {
        String imie =
            poleImie.getText().toString();
        labelWynik.setText("Witaj, " + imie + "!");
        Toast.makeText(
            getApplicationContext(),
            "Kliknięto przycisk!",
            Toast.LENGTH_SHORT
        ).show();
      }
    });
  }
}

Diagram przepływu — od kliknięcia do wyniku

Kliknięcie→onClick()→Pobierz tekst→Wyświetl wynik
Kliknięcie

Użytkownik dotyka przycisku na ekranie — punkt startowy całej akcji.

onClick()

Java automatycznie wywołuje tę metodę w odpowiedzi na kliknięcie — tu piszemy logikę.

Pobierz tekst

Odczytujemy wpis użytkownika przez .getText().toString().

Wyświetl wynik

Pokazujemy efekt przez setText() na TextView albo przez Toast.

Zapamiętaj ten schemat — bez względu na treść zadania zawsze powtarza się ten sam wzorzec: kliknięcie → pobranie danych → przetworzenie → wyświetlenie wyniku.

Najczęstsze błędy uczniów — i jak ich unikać

findViewById() przed setContentView()

Odwrócona kolejność powoduje Error — najpierw zawsze setContentView(R.layout.activity_main).

Brak .show() przy Toast

Najczęstszy błąd! Toast zostaje stworzony, ale nigdy się nie wyświetli. Zawsze kończ wywołaniem .show().

Brak android:id na widżecie

Bez id nie pobierzemy widżetu przez findViewById(). Nadawaj id wszystkim widżetom obsługiwanym w Javie.

Brakujące importy

Toast, Button, EditText wymagają linii import android.widget.XXX. Android Studio podpowie — Alt+Enter.

Niezgodność id w XML i w Javie

android:id="@+id/btnWitaj" w XML = R.id.btnWitaj w Javie — dokładnie ta sama nazwa. Literówka = błąd kompilacji.

Checklista przed egzaminem

Sprawdź, czy potrafisz wykonać każdy krok samodzielnie, bez pomocy:

Interfejs użytkownika (XML)

Zbudujesz LinearLayout z TextView, EditText i Button; nadasz każdemu widżetowi android:id.

Połączenie XML z Javą

Pobierzesz widżety przez findViewById() i podepniesz setOnClickListener() do przycisku.

Pobieranie danych z pola

Odczytasz zawartość EditText przez getText().toString() i użyjesz jej w logice.

Wyświetlenie wyniku

Wyświetlisz wynik przez setText() na TextView lub Toast.makeText(...).show().

WAŻNE — EGZAMIN

Java czy Kotlin? — wybór języka na egzaminie

Na INF.04 możesz pisać aplikację mobilną w Javie LUB Kotlinie — oba języki akceptuje CKE (oficjalne rozwiązania CKE często używają Kotlina). Wybierz ten, który znasz lepiej.

Java (ten kurs):

// Pobranie widżetu
TextView label = (TextView) findViewById(R.id.label);

// Obsługa kliknięcia
button.setOnClickListener(new View.OnClickListener() {
    @Override
    public void onClick(View v) {
        label.setText("Kliknięto!");
    }
});

// Pobranie tekstu z EditText
String tekst = editText.getText().toString();

Kotlin (alternatywa):

// Pobranie widżetu
val label = findViewById<TextView>(R.id.label)

// Obsługa kliknięcia — krócej!
button.setOnClickListener {
    label.text = "Kliknięto!"
}

// Pobranie tekstu z EditText
val tekst = editText.text.toString()

    Zadania na lekcję

    Pięć zadań z lekcji — rozwiązujesz je w Placu zabaw (XML + Java), a tutaj klikasz Sprawdź. Sprawdzarka naprawdę uruchamia Twoją aplikację, wpisuje dane i klika przyciski. Rób po kolei: każde kolejne rozbudowuje poprzednie.

    Praca domowa

    Zadania 1–4 możesz w całości przećwiczyć tutaj (Integer.parseInt, if-else, licznik i toUpperCase działają w symulatorze), ale finalnie wykonaj je w prawdziwym Android Studio. Do zadania 5 wczytaj przykład „Egzamin INF.04 czerwiec 2023" i przeanalizuj kod.

    Milionerzy — teoria do egzaminu

    12 pytań z lekcji, od 500 zł do miliona. Masz dwa koła ratunkowe (50:50 i głos publiczności) na całą grę. Progi gwarantowane: 1 000 zł i 40 000 zł. Zła odpowiedź = spadasz do progu i grasz od nowa.

      Znajdź błąd

      Każdy fragment zawiera dokładnie jeden błąd — taki, który naprawdę zdarza się na egzaminie. Kliknij linijkę, w której się czai.

      Ściąga

      Najważniejsze wzorce z lekcji — dokładnie w tej formie zapisujesz je na egzaminie INF.04. Przycisk kopiuje fragment do schowka.
